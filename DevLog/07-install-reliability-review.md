# 安装可靠性改进：Codex 复审记录

日期：2026-11-11。审查对象为当时的工作区，尚未提交 Git。

## 起因

现场更新 1.17.49.0 → 1.17.51.0 时，替换 `bearer/qgenericbearer.dll` 报"无法删除要被替换的文件"，回滚同样失败，事务停在 `RollbackFailed`，软件被挡住无法启动。该 DLL 新旧内容完全相同。

本机复现：DLL 被另一个进程以可执行映像方式映射时，`File.Replace` 时而成功、时而报同样的错误，取决于 Windows 内部缓存状态；同样情况下改名始终可行。

## 改动概要

- 第一层，宿主关闭前：检查磁盘空间、每个要变化目录的写权限。
- 第二层，宿主关闭后、改动任何文件前：只计划内容真正变化的文件（逐文件 SHA-256 比对），等待被占用的文件最多 15 秒。仍不行就写入无记录的 `RolledBack`，不写 pending，并询问是否重新打开原程序。
- 第三层，替换时：
  - 默认使用原子 `File.Replace`；
  - 被拒绝时，非入口文件退而"改名挪开再放入"，入口 EXE 绝不改名；
  - `File.Replace` 失败后若目标已不存在（错误码 1176），立即放入新文件；
  - 替换前清除只读属性；
  - 回滚时若目标已是原版则跳过；
  - 遗留文件只清理本安装器生成、且不受保留规则与签名清单保护的文件。
- 宿主：启动时发现未完成事务且安装锁空闲，自动执行 `recover --restart`，宿主自身静默退出，由更新器恢复后重开。安装或恢复进行中再次启动时宿主立即退出，提示由 Windows PowerShell 显示，避免宿主进程阻塞安装。

## 复审轮次

| 轮次 | 主要意见 | 处理 |
|---|---|---|
| 1 | 发布时服务端读取 `latest.json` 未共享删除权限，导致发布替换失败 | 服务端改为 `FileShare.Read \| FileShare.Delete`；原子写入遇占用短暂重试 |
| 2 | 三段与四段版本号未统一比较，可能复用已占用版本号 | 一键发布脚本统一补成四段再比较 |
| 3 | 改名窗口内崩溃可能使入口 EXE 缺失；清理可能误删保留数据；恢复期间宿主弹窗会阻塞恢复 | 入口 EXE 只用原子替换；清理跳过保留路径与签名清单文件；被阻止的宿主立即退出 |
| 4 | `File.Replace` 部分失败后目标可能已被删除；旧版更新器不支持新的提示命令 | 失败后检查目标是否存在并立即补齐；提示改由 PowerShell 显示，与更新器版本无关 |

## 验证

- 核心 31 项、发布包 16 项、安装流程 18 项、服务端 5 项、签名 8 项测试全部通过。
- Monitor（Qt/MSBuild）与 Manager（C#）编译通过。
- `File.Replace` 被拒绝无法在系统层面稳定复现，测试通过仅在测试进程中可用的反射开关 `SimulateReplaceRefused` 模拟；只读属性和映像映射场景使用真实文件测试。
